> 日期：2026-08-05

## 一、目标

将低保真线框图升级为高保真视觉稿，使面试官看到的 Figma 原型直接接近最终网站效果。所有视觉规范严格遵循 [07-设计系统.md](../docs/phase3-方案/07-设计系统.md) 中的 token 定义。

## 二、当前状态

| 维度 | 低保真现状 | 高保真目标 |
|---|---|---|
| 颜色 | 灰度 `#E8E8E8` / `#999999` / `#666666` | 品牌蓝 `#3B82F6` + 紫色点缀 + 完整配色层级 |

| 图标 | 无 | lucide-react 对应图标（📧 → Mail, 🔗 → Link, ☰ → Menu） |
| 动效 | 标注箭头文字 | 无（高保真为静态视觉稿，动效在代码阶段实现） |

| 画板 | 尺寸 | 内容 |
|---|---|---|
| 桌面端-高保真 | 1280×~2800 | 全页面，真实内容 |
| 平板端-高保真 | 768×~3000 | 响应式适配 |
| 移动端-高保真 | 375×~3400 | 汉堡菜单折叠态 |

## 六、假设与决策

1. **新建 Figma 文件而非覆盖低保真文件**：低保真线框图保留作为设计过程物证，高保真新建文件，两者独立
2. **使用 `figma_execute` 批量创建**：利用 Figma MCP 的 JavaScript API 批量生成元素，比手动逐个创建效率高 10 倍以上
3. **不创建 Figma 变量/样式库**：当前阶段不需要，直接用色值即可。如果需要组件复用，后续可提取
4. **内容以用户实际背景为准**：姓名、项目名等使用用户提供的真实信息，不确定的用示例内容占位
5. **Figma Bridge 需要保持连接**：执行期间需要 Figma Desktop 中 Bridge 插件保持运行
