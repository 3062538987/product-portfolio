# 高保真 Figma 排版全面优化计划

> 日期：2026-08-05
> 状态：待执行
> 目标：对现有 Figma 高保真文件进行全面排版重构，解决布局错位、信息密度过高、视觉层次混乱等问题

---

## 一、当前问题诊断

通过分析 Figma 高保真文件 `rLBhRgOwY7wi3RH17bQJMl`（桌面端-高保真 1280×3876），发现以下关键问题：

### 1.1 布局对齐问题
- **Projects-BG 偏移**：`x: 158`，未居中（正确应为 `x: 0`，内容区居中对齐）
- **Section 标题偏移**：`x: 540`（相对于 Projects-BG 的 x: 158，实际 x: 698），未在 1280 宽度中居中
- **卡片内容溢出**：展开态卡片内文字宽度 596px 超过卡片宽度 540px，且 x: 104 相对卡片 x: 80，溢出到卡片右侧边界外

### 1.2 视觉层次问题
- **Hero 区域**：指标数字、标签、按钮、装饰元素之间缺乏呼吸感，元素堆叠过于紧凑
- **项目卡片**：展开态一张卡片包含 6+ 内容模块（背景、角色、方案、数据对比、复盘、交付物），视觉上「一堵墙」
- **Section 交替背景**：项目区域和关于我区域之间背景切换不自然

### 1.3 信息密度问题
- **展开态卡片**：内容文字过多且无视觉分组，面试官难以快速扫读
- **卡片之间的间距**：折叠卡片高度 200px 但内容描述与指标之间间距不足
- **整体页面过长**：3876px 对于桌面端过长，需通过更好的信息架构减少视觉疲劳

### 1.4 与设计系统的偏差
- 卡片边框：高保真中卡片边框为 `#3B82F6`（品牌蓝），设计系统规定折叠态为 `#E5E7EB`
- 卡片阴影：部分卡片缺少 `shadow-sm`
- 按钮尺寸：Hero 按钮高度 48px，设计系统规定主按钮 44px

## 二、优化方案

### 2.1 全局布局修复

**内容区标准化**：
- 所有 Section 使用统一的 960px 内容区宽度（根据设计系统响应式断点）
- 桌面端 1280px 画板中，内容区左右各留 160px
- 所有 Section 标题左对齐到内容区边界（x: 160），不再居中

**Section 间距统一**：
- Hero → 项目：120px（`py-32`）
- 项目 → 关于我：120px
- 关于我 → 文章：120px
- 文章 → 联系：120px
- 联系 → 页脚：80px

### 2.2 Hero 区域重构

**当前问题**：元素堆叠紧密，装饰元素位置不协调

**优化方案**：
- 头像左移：头像从 `x: 820` 移到 `x: 160`，与姓名区域对齐
- 姓名+定位语右移：保持在 `x: 160`，与头像形成上下排列
- 头像尺寸调整为 120×120（从 180×180 缩小），减少视觉压迫
- 装饰元素移到右侧 `x: 960-1280` 区域，作为视觉点缀而非主要元素
- 指标数字与标签组合：3 个指标作为独立「指标卡片」并排展示，每个宽 ~200px，带浅蓝背景
- CTA 按钮：主按钮 + 次按钮间距 16px，总宽度控制在 336px 以内

**布局结构**：
```
┌──────────────────────────────────────────────────┐
│ [头像 120×120]  姓名（48px Bold）                │
│                  定位语（18px）                   │  ← 左对齐
│                  一句话描述（16px）               │
│                  [标签1] [标签2] [标签3] [标签4]  │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐         │
│  │ +35%     │ │ 2.3万    │ │ 4.8分    │         │  ← 指标卡片
│  │ 转化率   │ │ 月活     │ │ 满意度   │         │
│  └──────────┘ └──────────┘ └──────────┘         │
│  [查看作品 ↓]  [下载简历]                        │
└──────────────────────────────────────────────────┘
```

### 2.3 项目卡片重构

**当前问题**：展开态信息过载，缺乏模块化分组

**优化方案**：

#### 折叠态卡片（3 张非展开卡片）
- 宽度：560px（从 540px 微调）
- 高度：自动（约 200px）
- 边框：`#E5E7EB`（还原设计系统规范）
- 结构：标题 + 标签行 + 一句话描述 + 3 指标数字 + 展开按钮
- 指标数字使用图标化展示（绿色 ↑ / 蓝色数字）

#### 展开态卡片（1 张展开卡片）
- 宽度：560px
- 边框：`#3B82F6`（品牌蓝，展开态标识）
- 头部：浅蓝背景 `#DBEAFE`，56px 高
- 内容分模块，每个模块之间用 `#E5E7EB` 分隔线分隔

**展开态内容模块化**：
```
┌──────────────────────────────────────┐
│ 项目名称                    展开中 ↑ │  ← 头部
├──────────────────────────────────────┤
│ 标签行                              │
├──────────────────────────────────────┤
│ 一句话描述                          │
├──────────────────────────────────────┤
│ 核心指标（3 个数字，图标化）        │  ← 关键数据区
├──────────────────────────────────────┤
│ 📋 背景与挑战                       │  ← 模块 1
│ 描述文字（2-3 行）                  │
├──────────────────────────────────────┤
│ 👤 我的角色与推动                    │  ← 模块 2
│ 描述文字（2-3 行）                  │
├──────────────────────────────────────┤
│ 💡 方案与决策                       │  ← 模块 3
│ 描述文字（2-3 行）                  │
├──────────────────────────────────────┤
│ 📊 数据对比                         │  ← 模块 4
│ Before: X  →  After: Y  (+Z%)       │
├──────────────────────────────────────┤
│ 🔄 复盘与反思                        │  ← 模块 5
│ 描述文字（2-3 行）                  │
├──────────────────────────────────────┤
│ 📎 相关交付物                        │  ← 模块 6
│ PRD文档 / 流程图 / 架构图           │
└──────────────────────────────────────┘
```

#### 卡片布局（2 列网格）
```
┌──────────────────┐  ┌──────────────────┐
│  Card 1（展开）  │  │  Card 2（折叠）  │
│                  │  │                  │
│  (约 620px 高)   │  │  (约 200px 高)   │
└──────────────────┘  └──────────────────┘
┌──────────────────┐  ┌──────────────────┐
│  Card 3（折叠）  │  │  Card 4（折叠）  │
│                  │  │                  │
│  (约 200px 高)   │  │  (约 200px 高)   │
└──────────────────┘  └──────────────────┘
```

### 2.4 关于我区域优化

**当前问题**：时间线 + 职业目标卡片 + 技能标签混杂在一起

**优化方案**：
- 采用两栏布局：左侧个人陈述（60%），右侧技能标签（40%）
- 职业目标卡片：独立于时间线，放在个人陈述下方
- 时间线：使用蓝色竖线 + 圆点，简洁 3 条（教育背景、实习经历、项目经历）
- 技能标签：8 个标签，2 行 × 4 列排列，`#DBEAFE` 浅蓝背景

### 2.5 文章区域优化

**当前问题**：3 篇文章卡片排列过于密集

**优化方案**：
- 文章卡片改为全宽（960px），每张卡片高度约 100px
- 结构：左侧 4px 蓝色竖线 + 标题 + 日期 + 摘要
- 卡片之间间距 16px
- 3 张卡片总计约 350px，比重合理

### 2.6 联系 + 页脚优化

**优化方案**：
- 联系方式：居中排列，3 行（邮箱、微信、GitHub），每行图标 + 文字
- 社交按钮：4 个按钮水平居中排列，`#3B82F6` 边框 + 蓝色文字
- 页脚：简化为一句话版权信息，`#9CA3AF`，12px

## 三、实施步骤

### Step 1：连接 Figma 并获取当前状态
- 使用 `figma_get_status` 确认 Figma Bridge 连接状态
- 使用 `figma_navigate` 导航到高保真文件
- 使用 `figma_take_screenshot` 截取当前桌面端画板作为对比基准

### Step 2：全局布局修复
- 使用 `figma_execute` 运行 JavaScript 修复 Projects-BG 居中
- 统一所有 Section 的 x 坐标为 0 或 160（内容区）
- 调整 Section 标题位置

### Step 3：Hero 区域重构
- 调整头像位置和尺寸
- 重新排列姓名、标签、指标卡片
- 调整装饰元素位置
- 统一按钮尺寸为 44px

### Step 4：项目卡片完全重构
- 删除现有所有项目卡片节点
- 使用 `figma_execute` 批量创建新卡片结构
- 先创建展开态卡片（Card 1），再创建 3 张折叠态卡片（Card 2-4）
- 每张卡片内部模块化构建

### Step 5：关于我、文章、联系区域优化
- 调整关于我区域的布局
- 优化文章卡片样式
- 简化联系方式和页脚

### Step 6：全局检查与微调
- 使用 `figma_take_screenshot` 截取优化后画板
- 对比设计系统规范逐项检查
- 修复任何视觉不协调

### Step 7：文档更新
- 更新 `docs/phase4-原型/02-高保真视觉稿.md`
- Git commit 提交变更

## 四、验证标准

| 检查项 | 标准 |
|---|---|
| 内容区居中 | 所有 Section 内容区宽度 960px，左右各 160px |
| 卡片内容不溢出 | 所有文字宽度 ≤ 卡片宽度 - 48px（padding） |
| 卡片边框 | 折叠态 `#E5E7EB`，展开态 `#3B82F6` |
| 按钮尺寸 | 主按钮 44px 高，8px 圆角 |
| Hero 头像 | 120×120，圆角 16px |
| Section 间距 | 120px（桌面端） |
| 卡片阴影 | 折叠态 `shadow-sm`，展开态 `shadow-md` |
| 排版清爽 | 无内容溢出，模块间有明确分隔，面试官 30 秒内可扫读 |

## 五、假设与决策

1. **保留现有配色方案**：品牌蓝 `#3B82F6` + 绿色 `#10B981` + 橙色 `#F59E0B`，不做改动
2. **保留现有内容**：项目名称、描述、指标数字等文字内容不变，仅调整排版
3. **使用 `figma_execute` 批量操作**：通过 Figma Plugin API 的 JavaScript 批量创建/修改节点，效率高于逐个手动调用
4. **桌面端优先**：先完成桌面端画板优化，平板端和移动端后续适配
5. **不修改 Figma 变量/样式库**：当前阶段不需要，直接使用色值

## 六、风险与应对

| 风险 | 应对措施 |
|---|---|
| Figma Bridge 连接不稳定 | 操作前确认连接状态，关键步骤后截图验证 |
| `figma_execute` 批量操作失败 | 拆分为小步骤，逐步执行并验证 |
| 删除节点后无法恢复 | 操作前使用 Figma 的版本历史功能保存快照 |
| 卡片重构后内容丢失 | 先用 `figma_get_file_data` 备份所有文本内容 |
