## 十二、项目数量策略

基于竞品对比和用户决策，确定展示 **4 个项目**，原因如下：

| 竞品 | 项目数 | 评价 |
|---|---|---|
| 竞品 A | 6 个 | 太多，面试官只看 2-3 个，其余变噪音 |
| 竞品 B | 3 个 | 偏少，对校招 PM 广度不够 |
| 竞品 C | 2-4 个 | 灵活但质量不稳定 |
| 竞品 D | 2-4 个 | 受限于 PDF 篇幅 |
| **我们** | **4 个** | 面试官可选 2-3 个深读，每个都有独立记忆点 |

**4 个项目类型配比：**

| 顺序 | 定位 | 展示能力 | 策略 |
|---|---|---|---|
| 第 1 个 | 主打项目 | 产品全流程能力 | 最完整叙事，深度最足，先抓住面试官 |
| 第 2 个 | B 端 SaaS | B 端产品理解 | 与目标岗位直接相关，展示行业认知 |
| 第 3 个 | 数据驱动 | 数据分析与决策 | 展示数据思维，用数据讲故事 |
| 第 4 个 | 0-1 创新 | 探索与创新能力 | 展示从无到有，差异化亮点收尾 |

**排列逻辑：** 面试官从上往下滚动浏览，第一个项目决定"是否继续看"，第四个项目决定"最终印象"。所以主打项目放第一（抓住注意力），0-1 创新项目放最后（留下"有创造力"的印象）。

## 十三、结论

### 功能优先级建议

**P0（必须实现）：**
- 固定导航栏 + 锚点跳转 + 移动端汉堡菜单
- Hero 首屏（渐变背景 + 定位语 + 关键指标 + CTA 按钮）
- 项目卡片（折叠/展开 + 完整叙事链 + Before/After 图表）× 4 个项目
- 响应式布局（桌面端优先，移动端兜底）
- PDF 一键导出

**P1（应该实现）：**
- SEO 元标签 + OG 分享预览
- 滚动动效（fade-in）
- 悬停交互效果
- 附件下载区（PRD/流程图/原型）

**P2（可选实现）：**
- 暗色模式
- 社交媒体分享按钮

### 一句话总结

**功能上，我们不做最多的，但做最对面试官有用的——首屏抓注意力 + 4 个项目展深度 + 数据可视化说服力，是竞品都没做好的三件事。**
