# PM 项目工作流工具 — 设计文档

> 日期：2026-08-05
> 状态：已定稿

---

## 1. 项目概述

**目标：** 打造一套可复用的 PM 项目工作流工具，让每个新项目都经过标准化的 5 阶段流程（需求调研 → 方案设计 → 原型设计 → 开发实现 → 测试与上线），确保流程完整、产出物留痕。

**核心定位：** 不是"要不要走流程"的选择题，而是"怎么走流程更方便"的效率工具。通过看板可视化 + 目录脚手架，降低流程执行成本。

**使用场景：**
- 个人项目（网页、数据看板、小工具）
- 文档型项目（分析报告、竞品调研）
- 工作中可能用到的 PM 产品项目

## 3. 阶段流程（5 阶段）

### 阶段 1：需求调研

| 产出物 | 说明 |
|--------|------|
| 1.1 用户画像 | 目标用户特征、使用场景、痛点 |
| 1.2 用户故事 | 标准格式的用户故事 |
| 1.3 PRD | 背景、目标、功能需求（P0/P1/P2）、非功能需求、成功指标 |
| 1.4 干系人地图 | 涉及的角色和利益相关方 |
| 1.5 竞品分析报告 | 3-5 个竞品的多维度对比 |
| 1.6 功能对比矩阵 | 竞品功能横向对比表 |

### 阶段 2：方案设计

| 产出物 | 说明 |
|--------|------|
| 2.1 技术选型 | 候选方案对比（开发效率、维护成本、扩展性等维度） |
| 2.2 信息架构图 | 网站/产品整体信息层级和导航结构 |
| 2.3 系统架构图 | 组件树 + 前端架构 + 部署架构 |
| 2.4 页面设计 | 页面级线框图与布局规范，含响应式断点 |
| 2.5 交互设计 | 动效规范、过渡逻辑、微交互 |
| 2.6 数据流图 | 数据从源头到组件的完整流向 |
| 2.7 设计系统 | 配色、字体、间距、卡片、按钮、响应式断点规范 |
| 2.8 风险评估 | 项目风险 + 应对措施 |

### 阶段 3：原型设计

| 产出物 | 说明 |
|--------|------|
| 3.1 低保真线框图 | 页面布局草图 |
| 3.2 高保真视觉稿 | 关键页面视觉设计稿 |
| 3.3 交互说明 | 动效、过渡、交互流程文档 |

### 阶段 4：开发实现

| 产出物 | 说明 |
|--------|------|
| 4.1 项目代码 | 完整代码实现 |
| 4.2 数据文件/文档 | 内容数据、配置文件、README |

### 阶段 5：测试与上线

| 产出物 | 说明 |
|--------|------|
| 5.1 测试用例 | 功能测试、兼容性测试、响应式测试 |
| 5.2 验收报告 | 逐项对比 PRD 需求，标注通过/未通过 |
| 5.3 部署文档 | 部署流程、环境配置 |
| 5.4 上线检查清单 | 上线前逐项确认 |
| 5.5 复盘报告 | 目标达成、做得好的、可改进的、经验沉淀 |
| 5.6 迭代计划 | 后续优化方向和优先级 |

## 4. 看板设计

### 4.1 双视图

- **横向看板（默认）：** 经典三列布局（待开始 | 进行中 | 已完成），卡片可拖拽流转
- **纵向时间线：** 5 阶段自上而下排列，每个阶段可展开查看产出清单，带状态标签

### 4.2 新建项目向导

打开看板 → 点击"新建项目" → 进入向导：

1. 输入项目名称
2. 选择项目类型：
   - 完整版：5 阶段全部开启（适合带代码实现的项目）
   - 轻量版：默认关闭阶段 4（开发实现），可手动开启（适合纯文档/分析项目）
3. 勾选/取消各阶段开关
4. 确认创建 → 自动生成目录结构 + 看板任务卡片

### 4.3 卡片交互

- 每个阶段卡片可展开，内部列出该阶段所有产出物子任务
- 每个产出物旁边有「模板」按钮，点击生成对应的 Markdown 模板文件
- 子任务可拖拽流转状态
- 统计数据：完成率、各状态数量

### 4.4 数据存储

- 项目列表 + 所有任务状态存 localStorage
- 支持导出/导入 JSON（备份/迁移）
- 无后端依赖，纯前端

## 6. 技术方案

| 维度 | 选择 | 理由 |
|------|------|------|
| 技术栈 | 单文件 HTML + CSS + 原生 JS | 零依赖、零构建、双击即用 |
| 拖拽 | 原生 HTML5 Drag & Drop API | 无需引入第三方库 |
| 数据存储 | localStorage | 数据在浏览器本地，无需后端 |
| 数据导出 | JSON 文件下载 | 备份和迁移 |
| 模板生成 | 看板内触发 Markdown 模板下载 | 通过 Blob URL 下载 |
| 目录生成 | 看板内触发目录结构创建 | 通过浏览器下载 ZIP 展示目录结构 |
| 部署 | 单文件，拷贝即部署 | 可放 GitHub Pages 或本地使用 |

## 8. 假设与决策

1. 看板为单文件 HTML，数据存 localStorage，无后端
2. 不实现多用户协作，单用户使用
3. 目录生成通过浏览器下载 ZIP 包实现（而非直接写入文件系统）
4. 模板文件为 Markdown 格式，用户可自行修改
5. 工作流工具本身不强制流程顺序，看板只是可视化追踪，用户可灵活使用
6. 不包含时间管理、甘特图、日历等高级功能，保持轻量
7. 设计风格采用蓝/紫/灰配色，现代简洁风格，圆角+阴影+渐变
