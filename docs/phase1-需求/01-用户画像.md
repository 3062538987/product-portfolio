## 用户一：求职者（我自己）

| 维度 | 描述 |
|---|---|
| 身份 | 2027 届应届生，B 端产品经理方向 |
| 目标 | 秋招获得 B 端产品实习/全职 Offer，优先中厂，冲刺大厂 |
| 目标公司排除 | 初创公司（不考虑） |
| 痛点 | 简历篇幅有限，项目细节写不下；PDF 作品集不方便查阅和更新 |
| 动机 | 做网站既能展示项目深度，又能锻炼产品和技术能力 |
| 期望 | 简历上放链接，HR 点击后能清晰看到项目深度 |
| 核心印象目标 | 让面试官看完后觉得「这个人很适合做产品」 |
| 核心能力标签 | 产品思维、数据驱动、B 端 SaaS 理解、跨部门协作 |
| 差异化优势 | 拥有从 0 到 1 完整产品项目经验，能做完整的产品流程文档 |
| 使用场景 | 投递简历时附上链接，面试前更新项目内容，面试中现场演示 |
| 成功指标 | 面试官看完后主动在面试中提及作品集内容，邀请进入下一轮面试 |

## 用户二：面试官（目标读者）

| 维度 | 描述 |
|---|---|
| 身份 | 企业 HR（初筛）+ 业务面试官（深度评估） |
| 目标 | 快速判断候选人是否匹配岗位要求 |
| 场景 | 先看简历（15秒），有兴趣再点开作品集链接 |
| 核心关注点 | 项目深度和产品思维 > 设计品味 > 加载速度 > 个人信息 |
| 痛点 | 简历同质化严重，无法区分真实能力 |
| 期望印象 | 这个人有完整的产品思维闭环，不只是执行者 |
| 判断标准 | 有无产品思维闭环（发现问题→分析→方案→验证→复盘） |
| 黄金阅读时间 | 首屏 15 秒决定是否继续看，展开项目后 2-3 分钟深度阅读 |
| 使用设备 | 80% 桌面端（工作时间浏览），20% 移动端（碎片时间） |
| 决策路径 | 扫项目标题 → 看关键指标数字 → 展开一个项目 → 形成印象 → 决定是否邀请面试 |

|---|---|
