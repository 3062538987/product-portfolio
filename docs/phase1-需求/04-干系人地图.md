## 权力-利益矩阵

```
        高影响力
          │
    HR    │  求职者（我）
  初筛者  │  业务面试官
          │
  ────────┼───────── 高关注度
          │
  招聘平台│
          │
  GitHub  │
  同行/同学│
  社交平台│
          │
        低影响力
```

### 解读

- **右上象限（高影响力 + 高关注度）**：求职者、业务面试官 — 核心干系人，需求必须紧密满足
- **左上象限（高影响力 + 中关注度）**：HR 初筛者 — 必须让其快速获取关键信息
- **左下象限（低影响力 + 低关注度）**：GitHub、同行/同学、招聘平台、社交平台 — 保持告知即可

## 干系人影响链路

```
招聘平台 ──→ HR初筛者 ──→ 业务面试官 ──→ Offer
    │              │              │
    │    (简历+链接)  │  (深度阅读)   │  (面试中提及)
    │              │              │
    └────── 求职者（我）←─────────┘
                │
                ↓
          同行/同学 ──→ 社交平台 ──→ 被动机会
```

**关键链路说明：**
1. 求职者投递简历（含作品集链接）到招聘平台
2. HR 初筛者看到简历，点击链接 → 决定是否推给业务面试官
3. 业务面试官深度阅读作品集 → 决定是否邀请面试
4. 面试中提及作品集内容 → 加分项
5. 同行/同学在社交平台分享 → 可能带来被动机会

## 干系人管理策略

| 干系人 | 管理策略 | 具体行动 | 关键信息 |
|---|---|---|---|
| 求职者（我） | 紧密协作 | 全程参与讨论和决策，提供内容素材 | 进度、决策点、内容素材 |
| HR 初筛者 | 令其满意 | 首屏 15 秒内展示核心项目成果和关键数据 | 项目名称 + 3 个关键指标 |
| 业务面试官 | 重点管理 | 每个项目完整的 STAR 描述 + 复盘思考 | 项目深度、决策逻辑、数据对比 |
| 招聘平台 | 最低关注 | 确保链接格式正确，Open Graph 标签完整 | 链接预览正常 |
| 社交平台 | 最低关注 | 配置 Open Graph 标签，分享时有吸引人的预览 | 标题、描述、缩略图 |
| GitHub | 最低关注 | 正常 git push，README 保持更新 | 代码变更 |
| 同行/同学 | 最低关注 | 保持网站质量，自然传播 | 专业印象 |

## 风险干系人

| 干系人 | 风险 | 应对措施 |
|---|---|---|
| HR 初筛者 | 链接打不开或加载慢，直接跳过 | 确保 GitHub Pages 稳定，首屏加载 < 2 秒 |
| 业务面试官 | 内容不够深入，看完没有印象 | 每个项目必须有复盘思考，展示决策逻辑 |
| 招聘平台 | 部分平台可能屏蔽外部链接 | 准备短链接备用，PDF 作为兜底方案 |
