## 一、风险评估矩阵

风险等级 = 影响程度 × 发生概率。评分 1-5 分，≥12 分为高风险，8-11 分为中风险，≤7 分为低风险。

| # | 风险 | 影响 | 概率 | 等级 | 类别 |
|---|---|---|---|---|---|
| R1 | 内容素材准备不及时 | 4 | 3 | **12 高** | 进度 |
| R2 | 1 周时间不足以完成全部开发 | 4 | 3 | **12 高** | 进度 |
| R3 | react-to-print 与 Tailwind 样式冲突 | 3 | 3 | 9 中 | 技术 |
| R4 | GitHub Pages 部署后静态资源路径错误 | 4 | 2 | 8 中 | 技术 |
| R5 | 移动端响应式效果不理想 | 2 | 3 | 6 低 | 体验 |
| R6 | 浏览器兼容问题（Safari 特殊行为） | 2 | 2 | 4 低 | 兼容 |
| R7 | Power BI 导出的图表图片清晰度不足 | 2 | 2 | 4 低 | 内容 |
| R8 | 折叠/展开动画性能问题 | 2 | 2 | 4 低 | 性能 |
| R9 | 内容过于技术化，面试官看不懂 | 4 | 1 | 4 低 | 内容 |
| R10 | GitHub Pages 被墙或访问不稳定 | 5 | 1 | 5 低 | 部署 |

## 二、高风险应对

### R1：内容素材准备不及时

- **影响：** 网站开发完成后无内容填充，无法上线
- **应对：**
  - 需求阶段即开始并行准备内容素材（见甘特图中"内容填充"并行线）
  - 先搭建框架和样式，内容用占位数据，后续替换
  - 设定内容素材 DeadLine：不晚于开发阶段结束前 1 天
- **触发条件：** 开发完成但内容素材仍未就绪 → 先用占位数据上线，后续补充

### R2：1 周时间不足以完成全部开发

- **影响：** 无法按时上线，影响秋招投递节奏
- **应对：**
  - 严格按 P0 → P1 → P2 优先级开发，P2 功能可延后
  - 使用 AI 辅助（Trae Work）加速开发
  - 使用 Tailwind CSS 原子化样式，减少 CSS 编写时间
  - 如时间不足，P1 功能（SEO、OG 标签、滚动动效）可降级为 P2
  - 核心底线：P0 全部完成即可上线
- **触发条件：** 开发第 3 天结束时 P0 完成度 < 60% → 启动精简方案

## 三、中风险应对

### R3：react-to-print 与 Tailwind 样式冲突

- **影响：** PDF 导出排版错乱
- **应对：** 为 PDF 组件单独写 print 样式，用 `@media print` 覆盖 Tailwind；使用 `react-to-print` 的 `content` 回调自定义渲染逻辑
- **兜底：** 如果 PDF 导出实在无法完美，可手动准备一份 PDF 简历作为下载文件

### R4：GitHub Pages 部署后静态资源路径错误

- **影响：** 页面白屏，CSS/JS 加载失败
- **应对：** Vite 配置 `base: '/product-portfolio/'`，构建后本地验证 `dist/` 目录；部署前用 `npx serve dist` 本地预览

## 四、低风险应对

| 风险 | 应对措施 |
|---|---|
| R5 移动端响应式不理想 | 80% 桌面端优先，20% 移动端兜底；用 Tailwind 响应式断点快速适配 |
| R6 浏览器兼容问题 | 仅兼容 Chrome/Edge/Safari 最新两个版本，不兼容 IE |
| R7 图表图片清晰度不足 | 导出时选择 2x 分辨率，确保移动端和桌面端都清晰 |
| R8 折叠/展开动画性能问题 | 用 CSS `transform` 和 `opacity` 做动画，GPU 加速；避免 `height` 动画 |
| R9 内容过于技术化 | 内容撰写时对照"面试官想看什么"指南自查；请非技术同学试读 |
| R10 GitHub Pages 被墙 | 概率极低；如发生，可迁移到 Vercel/Netlify（同样免费，10 分钟迁移） |

## 五、风险监控机制

| 阶段 | 监控节点 | 检查内容 |
|---|---|---|
| 需求阶段结束 | Day 1 末 | 内容素材完成度 ≥ 50% |
| 方案设计结束 | Day 2 末 | 所有设计文档定稿，技术方案确认 |
| 开发中 | Day 3 末 | P0 功能完成度 ≥ 60%，否则启动精简方案 |
| 开发结束 | Day 5 末 | P0 全部完成，P1 完成度 ≥ 80% |
| 测试阶段 | Day 6 | 3 个测试视口通过，PDF 导出正常 |
| 上线前 | Day 7 | 上线检查清单全部通过 |
