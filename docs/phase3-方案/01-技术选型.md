## 二、决策评分矩阵

评分维度（1-5 分，5 分最优）：

| 评分维度 | 权重 | 方案 A | 方案 B | 方案 C |
|---|---|---|---|---|
| 开发效率 | 25% | 3 | 4 | 3 |
| 技术熟悉度 | 25% | 3 | 5 | 2 |
| 扩展性 | 15% | 2 | 5 | 4 |
| 维护成本 | 15% | 4 | 4 | 3 |
| 部署简易度 | 10% | 5 | 4 | 4 |
| 生态丰富度 | 10% | 1 | 5 | 3 |
| **加权总分** | **100%** | **3.05** | **4.55** | **3.10** |

### 维度详解

**开发效率（25%）：** 1 周时间，代码量越少越好。方案 B 有 AI 辅助（Codex + Trae Work），React 组件复用效率高。

**技术熟悉度（25%）：** 我熟悉 React，方案 B 最匹配。

**扩展性（15%）：** 后续可能加博客、搜索等功能，方案 A 扩展困难，方案 B 组件化扩展方便。

**维护成本（15%）：** 内容更新频率。方案 B 数据文件驱动，修改 JSON 即可。

**部署简易度（10%）：** GitHub Pages 部署。方案 A 最简单，方案 B 需要 build 步骤但有 CI 自动化。

**生态丰富度（10%）：** 第三方库支持。方案 B 有 react-to-print、图表库等丰富生态。

## 三、方案 B 详细技术选型

### 核心技术

| 层 | 选择 | 版本 | 理由 |
|---|---|---|---|
| 构建工具 | Vite | 5.x | 快速 HMR，零配置 React 支持 |
| UI 框架 | React | 18.x | 我熟悉，组件化，生态最大 |
| 样式方案 | Tailwind CSS | 3.x | 原子化 CSS，快速开发，响应式方便 |
| 语言 | TypeScript | 5.x | 类型安全，减少运行时错误 |

### 功能依赖

| 功能 | 依赖库 | 理由 |
|---|---|---|
| PDF 导出 | `react-to-print` | 成熟的 React 打印方案，支持 A4 排版 |
| 图表（Before/After 对比） | 纯 CSS 实现 | 数据量小，无需引入图表库，减少包体积 |
| 图标 | `lucide-react` | 轻量、Tree-shaking 友好、图标丰富 |
| 滚动动效 | 纯 CSS animation + Intersection Observer | 无需额外库，fade-in 效果原生实现 |
| 部署 | `gh-pages` | 一键部署到 GitHub Pages |
| 代码质量 | ESLint + Prettier | Vite 模板自带，零配置 |

### 不需要的

| 不引入 | 理由 |
|---|---|
| 状态管理库（Redux/Zustand） | 纯静态展示，数据从文件读取，无需全局状态 |
| 路由库（React Router） | 单页应用，锚点导航即可 |
| 图表库（Recharts/ECharts） | 只有 2-3 个简单对比数据，CSS 实现更轻量 |
| UI 组件库（Ant Design/MUI） | 自定义设计系统，不引入重型组件库 |
| 后端框架 | 纯静态，无后端需求 |

## 八、技术风险与应对

| 风险 | 影响 | 概率 | 应对措施 |
|---|---|---|---|
| react-to-print 与 Tailwind 样式冲突 | PDF 排版错乱 | 中 | 为 PDF 组件单独写 print 样式，用 `@media print` 覆盖 |
| GitHub Pages 部署后静态资源路径错误 | 页面白屏 | 中 | Vite 配置 `base: '/product-portfolio/'`，构建时验证 |
| Tailwind 3.x 升级到 4.x 不兼容 | 样式失效 | 低 | 锁定版本号，不自动升级 |
| TypeScript 类型定义不完整 | 编译报错 | 低 | 使用 `any` 兜底，后续补类型 |
| 折叠展开动画性能问题 | 移动端卡顿 | 低 | 用 CSS transform 而非 height 动画，GPU 加速 |
